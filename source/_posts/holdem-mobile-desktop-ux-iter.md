## 0. 目标：手机端一屏玩得下，而且像真的牌桌

桌面端其实比较“好伺候”：空间够大，牌桌、座位、日志、按钮都能摆。

真正麻烦的是手机端——我想要的不是把桌面端“缩小塞进手机”，而是做一个**专门的手机布局**：

1) 桌子中间只放最重要的信息：**5 张公共牌 + 底池（总注）**
2) 6 个玩家信息框围绕牌桌（在桌外），每个玩家的两张手牌也在桌外
3) 底部固定一条操作区，避免滚动、避免误触
4) 结算时能看懂：弃牌/牌型/获胜，停留几秒再进入下一局

这套目标看起来像“改几个 CSS”，但实际牵扯到 **布局、层级、裁切、缓存、以及自动下一局的节奏控制**。

---

## 1. 文件结构：哪些文件负责手机/桌面？

这个游戏是以 Hexo 静态资源的方式发布的：`source/holdem/` 会被原样拷贝到最终站点。

核心文件：

- `source/holdem/index.html`：页面结构（桌面布局 + 手机布局的 DOM 都在这里）
- `source/holdem/styles.css`：桌面端样式 + 通用样式
- `source/holdem/mobile.css`：手机端专属样式（我最后选择“分文件维护”，而不是把手机规则塞进同一个 CSS）
- `source/holdem/app.js`：逻辑（发牌/下注/摊牌/渲染/自动下一局/按钮交互）

我强烈建议：**手机端单独一个 `mobile.css`**。因为当你要调“座位在桌外”的毫米级位置时，混在桌面 CSS 里会非常痛苦。

## 2. 一开始踩的坑：为什么“桌外的牌”会突然看不到？

手机端把手牌移到桌外，最常见的两类失败：

- **被裁切**：父容器 `overflow:hidden` 或某个内部容器把溢出内容裁掉
- **被盖住**：层级（z-index/stacking context）不对，牌在桌面下面

我最终的经验是：

- 桌子容器（以及内层）必须允许溢出：`overflow: visible`
- 牌/座位需要明确 `z-index`

但更稳的一步是：

> 不要只把“牌(row3)”单独绝对定位到桌外。
> 
> 直接把**整个座位框（包含两张牌）**摆在桌外，牌在座位框内部正常 flow。

这样你不需要和“row3 往外挪多少像素才不出屏幕”死磕。

## 3. 手机端布局：把桌子变窄，让两侧真正有“桌外区域”

如果牌桌宽度是 `100%`，你会发现一个现象：

- 左右两侧的玩家明明写的是“桌外”，视觉上仍然像压在桌边
- 甚至会发生左右玩家牌被屏幕裁掉

原因很简单：桌子占满了整个屏幕，左右根本没有空间。

所以我用了一个很直接、可复现的布局策略：

- 先定义“座位框宽度变量”：`--m-seat-w`
- 再把牌桌宽度变成：

```css
.oval{
  width: calc(100% - (var(--m-seat-w) * 2) - (var(--m-side-gap) * 2));
  margin: 0 auto;
}
```

这句话的含义是：

- 中间的桌子**主动让出左右两条走廊**
- 左右走廊的宽度足够容纳座位框
- 这样“座位在桌外”就不是靠运气，而是布局保证

同时我把牌和桌子都做了 `clamp()`，避免某个机型突然爆炸：

```css
--m-card-w: clamp(24px, 6.6vw, 30px);
--m-card-h: calc(var(--m-card-w) * 1.35);
--m-seat-w: clamp(84px, 22vw, 128px);
```

## 4. 自动下一局：从“按钮”到“可控的中场时间”

我最初做的是彻底删除“新的一局”按钮，让游戏自动进入下一局。

后来在手机端体验里我发现：

- 新手会看牌很慢
- 有时你想多看 10 秒复盘
- 有时你看懂了又希望立刻下一局

所以现在的逻辑变成：

- 默认 5 秒自动下一局
- 下拉选择 2/5/8/10 秒
- 增加一个 **“手动下一局（无限等待）”** 选项
- **按钮“新的一局”保留**：无论你选了多少秒，都可以立刻跳到下一局
- 结算期间显示倒计时：`下一局 8s` … 或 `下一局 ∞`

对应改动在：

- `index.html`：新增下拉 `#m-nextDelay`、倒计时 `#m-nextCountdown`、按钮 `#m-btnNextHand`
- `app.js`：
  - `scheduleAutoNextHand()` 读取下拉
  - `-1` 代表手动模式（不 setTimeout）
  - 用 `setInterval` 刷新倒计时显示

## 5. 结算信息：弃牌红色，牌型黑色加粗

我把“玩家状态栏”当成一个 HUD（抬头显示），结算时直接告诉你每个人是什么牌。

规则：

- `弃牌`：红色（更醒目）
- `未弃牌`：显示牌型（黑色加粗）

为了复现方便，我在 `app.js` 里加了一个粗分类函数 `handCategory7(cards)`，它不会像专业 evaluator 那样精确到 kicker，但能稳定分出：

- 高牌 / 一对 / 两对 / 三条 / 顺子 / 同花 / 葫芦 / 四条 / 同花顺

然后在结算（摊牌/或所有人弃牌）时，给每个座位写一个 `roundStatus`，渲染时优先显示这个字段。

## 6. 部署与缓存：为什么我一直在改 ?v=xxx

移动端调 UI 最折磨人的事情不是 CSS，而是缓存。

GitHub Pages + 手机浏览器经常会：

- HTML 更新了，但 CSS/JS 还在旧版本
- 或者你明明改了 JS，手机却死活不生效

我采取的策略很土，但很好用：

- 对 `styles.css`、`mobile.css`、`app.js` 全部加 query version：
  - `mobile.css?v=...`
  - `app.js?v=...`

每次关键修复我都 bump 一次版本号。

## 7. 你想复现同样的手机端效果，照着做就行

最小复现步骤：

1) 在 `source/holdem/index.html` 引入 `mobile.css`（并确保有 mobile DOM：`m-seat-*`、`m-community`、底部操作栏）
2) 在 `source/holdem/mobile.css`：
   - 让 `.oval` 不是 100% 宽（给左右座位留走廊）
   - 6 个座位框都用 absolute 放在桌外
3) 在 `source/holdem/app.js`：
   - 渲染 mobile seat 的 row3 两张牌
   - 结算时写入 `roundStatus`
   - 自动下一局 + 可配置延时 + 手动模式

## 结语：我更喜欢“能玩、能看懂、能复盘”的德州扑克

这套实现不追求 solver 水平，但我追求三件事：

- 打起来顺手（尤其是手机）
- 结算看得懂（弃牌/牌型/倒计时）
- 逻辑能复现（你照着改，能做出同样效果）

下一步如果继续进化，我会优先补：

- 侧池（all-in 后的分池）
- 更严格的 hand evaluator（真正的牌型比较，而不是启发式 strength）
- 更精细的玩家动作提示（谁行动、需要跟多少）
